# 小红书笔记图片制作

用于创建可直接发布到小红书的图片笔记。3:4 比例 (1080×1440)，以图片序列呈现内容。

## 规范

- **比例**：3:4 (1080×1440px)
- **格式**：PNG，白底或浅色背景
- **配色**：主色 + 强调色（不超过 3 色），参考 `assets/palettes.json`
- **安全区**：左右各留 60px，上下各留 60px，避免平台裁切

### 字号铁律（不可违反）

| 元素 | 最小值 | 推荐值 | 违反后果 |
|------|--------|--------|----------|
| 封面主标题 | 100px | 120-140px | 缩略图看不清 |
| 封面副标题 | 48px | 56-64px | 同上 |
| 内容页标题 | 52px | 56-64px | 手机端吃力 |
| 正文/卡片标题 | **30px** | 32-36px | **28px 以下手机端不可读** |
| 正文/卡片内容 | **28px** | 28-32px | **26px 以下不可接受** |
| 注释/小字 | **24px** | 24-28px | **22px 以下不可接受** |
| 编号标签 | 28px | 30-32px | — |
| 金句框文字 | 30px | 32-36px | — |

⚠️ **底线：任何文字不得小于 24px。** 写 CSS 时逐个检查每个 font-size，发现 < 24px 立即改大。

**反面案例（禁止出现）：**
```css
/* ❌ 错误：正文太小 */
.card-text { font-size: 23px; }  /* 必须 ≥ 28px */
.compare-sub { font-size: 18px; }  /* 必须 ≥ 24px */
.bar-val { font-size: 20px; }  /* 必须 ≥ 24px */
```

## 标准结构

1. **封面**（第 1 张）— 大标题 + 副标题 + 人物/图标，一眼抓注意力
2. **内容页**（第 2~N 张）— 每页一个核心观点，图文并茂
3. **结尾页**（最后 1 张）— 总结/引导关注/CTA

每页信息密度控制：标题 1 行 + 正文 ≤ 5 行 + 图标/图表

### 空间利用规范

1080×1440 的画布必须被内容合理填满，不能出现大面积空白。

| 区域 | 规范 |
|------|------|
| 内容区 padding | 上下 60-70px，左右 60px |
| 标题与首个内容块间距 | 28-36px |
| 卡片/内容块之间间距 | 16-24px |
| 底部金句框距底部 | 60px（固定定位） |
| 内容区底部到金句框 | 至少留 40px 间距 |

**原则：内容应该占据画面 70-85% 的高度。** 如果内容只占了 50% 以下，说明字号太小或内容太少，需要放大字号或增加内容。

### 封面设计铁律（第 1 张）

**核心原则：缩略图也能看清。** 小红书笔记在信息流列表中会被缩小很多倍展示，封面必须字少、字大、高对比。

| 要求 | 规范 |
|------|------|
| **文字量** | 总文字 ≤ 15 个汉字（英文/数字另算） |
| **主标题字号** | ≥ 100px，加粗，占封面 50%+ 面积 |
| **副标题字号** | ≥ 48px |
| **配色** | 深色背景 + 亮色文字，或白底 + 深色文字，对比度要强 |
| **布局** | 居中对齐，上下留白充足 |
| **标签/角标** | 可选，≤ 5 个字，放顶部或底部 |
| **禁止** | 长句子、小字说明、密集排版、多层嵌套信息 |

**参考风格：** 深色背景 + 大字标题 + 关键数据（数字 > 文字）+ 底部标签，类似「AI 自己提 Bug？」这种一句话抓眼球的效果。

## 内容合规红线（不可违反）

小红书对违规内容处罚严厉：限流 → 不可查看 → 封号。生成笔记文案时必须逐条检查。

### 禁止话题（直接封杀）

| 类别 | 具体内容 | 处罚等级 |
|------|----------|----------|
| 境外服务 | GPT/Claude 等境外 AI 工具注册、账号交易、翻墙教程 | 不可查看 |
| VPN/翻墙 | 任何 VPN 推荐、翻墙方法、科学上网 | 不可查看 |
| 未认证软件 | 分享破解版、激活码、未上架应用商店的软件 | 不可查看 |
| 政治敏感 | 涉及政治人物、时政评论、敏感历史事件 | 封号 |
| 虚假宣传 | 夸大功效、虚假承诺、未经证实的数据 | 限流/删除 |

### 限流话题（需包装）

| 类别 | 规避方式 |
|------|----------|
| 测评对比 | ❌ 不做排名/拉踩 → ✅ 改为「体验分享」「各有特色」 |
| 竞品评价 | ❌ 不贬低竞品 → ✅ 只说各自适用场景 |
| AI 工具 | ❌ 不提境外工具名 → ✅ 用「某AI」「国产平替」代替 |
| 价格/收益 | ❌ 不写具体金额承诺 → ✅ 用「有机会」「参考」等模糊表述 |

### 文案措辞规范

**对比类内容铁律：**
- ❌ 禁止：「XX完爆YY」「XX吊打竞品」「XX最差」「别用YY」
- ✅ 改为：「XX更适合XX场景」「个人体验下来，XX在XX方面更顺手」「两者各有千秋」
- ✅ 每个产品至少说 1 个优点 + 1 个适用场景
- ✅ 结尾用「个人体验，仅供参考」收尾

**AI/科技类内容铁律：**
- ❌ 禁止：直接提及 GPT、Claude、Claude、Gemini 等境外工具名
- ✅ 改为：「某AI」「国产AI工具」「平替工具」
- ❌ 禁止：提供注册链接、邀请码、优惠码
- ✅ 改为：感兴趣的自己搜索了解

**数字/数据铁律：**
- ❌ 禁止：「注册送300美金」「月入10万」「100%有效」
- ✅ 改为：「有机会获得」「官方有活动」「实测有效（附截图）」
- 所有数据必须有来源或实测依据

### 自检清单（文案生成后必须执行）

生成文案后，逐条检查：
- [ ] 无境外工具/服务直接名称
- [ ] 无 VPN/翻墙/科学上网相关内容
- [ ] 无竞品贬低性措辞（完爆/吊打/最差/别用）
- [ ] 无虚假数字承诺（具体金额/收益/100%）
- [ ] 对比类内容每个产品都有正面描述
- [ ] 结尾有免责提示（个人体验/仅供参考）

## 工作流

1. 确认主题、受众
2. **确认风格**（如老板未指定，先询问选择）
3. 出 v1 草稿（封面 + 3~5 内容页 + 结尾）
4. **⚠️ 强制自检自修**（见下方详细流程）
5. 老板反馈 → 逐轮修改（每次只改一个点）
6. 检查 emoji 渲染（必须看预览图）
7. 导出最终 PNG + 打包 zip

### 自检自修流程（第 4 步，不可跳过）

生成所有 HTML 后、渲染 PNG 前，**必须执行以下自检**：

**Step 1：渲染预览**
用 sharp 将所有 HTML 渲染为 PNG。

**Step 2：逐页审查**
用 image 工具查看每张渲染后的 PNG，逐页检查：
- 字号是否够大？（手机端能否看清）
- 卡片是否有阴影/光效？（不能纯扁平）
- 背景是否渐变？（不能纯色 #000）
- 内容是否填满画面？（不能大面积空白）
- 文字是否被遮挡/溢出？
- 元素间距是否合理？

**Step 3：发现问题 → 立即修复**
- 不要等老板反馈，自己发现的问题自己改
- 修改 HTML → 重新渲染 → 再次检查
- 直到每页都达标为止

**Step 4：输出自检报告**
在交付时附上简要自检结果，格式：
```
自检完成：
- P1 封面：✅ 字号充足，装饰元素到位
- P2 内容1：✅ 卡片光效正常，间距合理
- P3 内容2：⚠️ 修复了 XX 问题（描述）
- ...
```

**核心原则：把自己当老板，用老板的眼光审视自己的作品。发现问题不等不靠，立即修复。**

## 踩坑记录

### SVG emoji 乱码
sharp + SVG 不加载 emoji 字体，emoji 会变方块。
**解法**：全部用纯文字符号（✓ ✗ ● ▲ → ★ 等），不用 emoji。

### 字号过小（高频问题）
3:4 比例下，正文 < 24px 在手机端几乎不可读。常见错误：正文写 23px、小字写 18-20px。
**解法**：写完 CSS 后，逐个检查每个 font-size 属性。任何值 < 24px 立即改大。推荐值：正文 28-32px，小字 24-28px。

### 内容过载
一页塞太多内容，小红书用户滑得快，看不清。
**解法**：每页 ≤ 1 个核心观点，文字精简，留白充足。

### 画面太空（高频问题）
内容字号太小 + 间距太大 = 大面积空白，看起来「没东西」。
**解法**：内容应占据画面 70-85% 高度。如果不到 60%，放大字号或增加内容块。

### 卡片太扁平
只有纯色背景+细边框，没有阴影/渐变/光效，视觉层次单一。
**解法**：所有卡片必须加 box-shadow 光效，背景用渐变而非纯色。参考上方 CSS 模板。

### 写完不检查（高频问题）
HTML 写完直接渲染交付，不回头看效果。常见后果：文字溢出、元素重叠、字号不够大。
**解法**：渲染后必须用 image 工具逐页审查。发现问题立即改 HTML 重新渲染，不要等老板反馈。

## 科技蓝 SaaS 简报风格规范

当选择「科技蓝 SaaS」风格时，遵循以下额外规范。该风格参考 Palantir/Semovix 等企业级技术传播的视觉语言，核心特征：**浅蓝渐变底 + 白色悬浮卡片 + 蓝色强调 + 3D 几何装饰**。

### 整体调性
- 专业、克制、信息密度高
- B2B SaaS / 企业级技术科普专用
- 不要过于花哨，以内容清晰传达为第一优先

### 编号标签系统
- 每页内容左上角放 **编号标签**：`01 它是什么` / `02 四层架构` / `03 核心组件`...
- 标签样式：圆角矩形，蓝色底色（#2B7DE9）+ 白色文字，字号 28-32px
- 封面页不放编号

### 标题排版
- 主标题：深色（#1A2332），≥ 72px，加粗
- 副标题：蓝色（#2B7DE9），≥ 48px
- 正文：深色（#1A2332），≥ 28px
- 关键词用蓝色高亮

### 卡片设计
- 白色圆角卡片（border-radius: 16px），悬浮在渐变底上
- 卡片必须有柔和阴影：`box-shadow: 0 4px 24px rgba(43,125,233,0.08)`
- 卡片内标题用蓝色或深色加粗
- 卡片之间间距 20-24px

### 底部金句框
- 每页底部放一个总结金句
- 样式：蓝色渐变底（#2B7DE9 → #1A5FCC）+ 白色文字，圆角矩形，字号 32-36px
- 内容：一句话总结本页核心观点

### 3D 几何装饰
- 标题区域附近放 **半透明蓝色 3D 几何体**（立方体、球体、圆柱体）
- 透明度 20-40%，不遮挡文字
- 用 CSS 渐变 + border-radius 模拟，不用图片
- 封面页可放 1-2 个大装饰，内容页放 1 个小装饰

### 视觉丰富度要求

**必须添加的视觉元素（不是可选，是必须）：**

1. **背景必须是浅蓝渐变，不能纯白或纯色**
2. **白色卡片必须有柔和阴影**
3. **标题区域附近必须有 3D 几何装饰**
4. **底部金句框必须有蓝色渐变背景**
5. **编号标签必须有蓝色底色**
